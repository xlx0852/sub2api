# 观测：2026-09-25 性能相关改动上线后的生产数据

数据源：`usage_logs.first_output_stages`（今天上线的分段采集）+ 网关访问日志 + 风控运行时状态。
时间窗：before = 13:00–14:45 (+08)，after = 14:45–15:16 (+08)（审核调参 14:32、gzip 生效 14:46、出站字节字段 14:52 起落库）。

## 1. 安全审核尾部（timeout 1200→400ms、retry 1→0）

| 指标 | before(1200ms/重试1) | after(400ms/无重试) |
| --- | --- | --- |
| 样本 | 380 | 127 |
| p50 / p90 / p95 | 49 / 347 / 387 ms | **31** / 434 / 500 ms |
| max | **2229 ms** | **598 ms** |
| ≥400ms | 16 | 19 |
| ≥1000ms | **7** | **0** |

结论：**1 秒以上的尾部被消除**（7→0，max 2229→598ms），中位数降 37%；400–600ms 区间出现次数占比略升，来自「400ms 超时 + 非 HTTP 环节（hash 命中检查/关键词扫描/采样判定）」的叠加，属于可接受范围。失败仍 fail-open 并计入 `pre_block_errors`。

## 2. 大请求体 gzip（上游白名单 o10.top，≥1MiB）

| 指标 | before | after |
| --- | --- | --- |
| 样本（>1MiB） | 258 | 62 |
| 入站 p50 | 9.25 MiB | 11.46 MiB |
| 出站 p50 | 9.22 MiB（未压） | **7.30 MiB** |
| 出站/入站 p50 | 100% | **63.6%** |
| `upstream_write_ms` p50 / p95 | 690 / 1969 ms | 843 / 2500 ms |
| 每出站 MiB 写耗时 p50 | 74.8 ms | 117.0 ms |

结论：**压缩确实生效**（早前 2.68MiB 样本可到 29.5%），但
1. 这类 11MiB 级 Codex 载荷压缩比只有 ~64%（内容熵高，非图片：`image_count=0`）；
2. 写耗时由「约 250–300ms 固定开销 + 每 MiB 变量项」构成，压缩带来的字节下降**没有转化为端到端收益**，且 after 窗口的请求体本身更大（11.46 vs 9.25 MiB）。

可跟进：把压缩级别从 `BestSpeed` 提到 `Default`（本地 CPU 换更小字节），或对白名单上游改试 zstd（需先验证上游支持）。
