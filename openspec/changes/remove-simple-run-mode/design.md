## Context

当前 `simple` 模式是跨后端和前端的行为分支。后端会绕过部分 API Key 配额、余额扣费、分组隔离与定时任务；前端会隐藏用户、分组、用量、充值、利润和风控等入口。数据库启动阶段还会创建简洁模式默认分组并提升管理员并发。

## Goals / Non-Goals

- Goals:
  - 运行时只保留一套标准语义。
  - 防止旧简洁模式部署在升级时静默改变扣费或调度行为。
  - 删除前后端所有简洁模式条件分支和专用维护代码。
- Non-Goals:
  - 不自动删除简洁模式曾创建的分组、账号或用户数据。
  - 不自动推断生产环境应采用的渠道、定价或配额配置。
  - 不改变标准模式现有行为。

## Decisions

- Decision: 配置值 `simple` 变为明确的启动错误，而不是归一化为 `standard`。
  - Reason: 静默回退会立即启用标准模式计费、配额和分组隔离，可能造成生产流量中断或意外扣费。
- Decision: API 登录和用户响应不再返回 `run_mode`。
  - Reason: 前端不再需要运行模式分支，继续暴露该字段会形成无效兼容面。
- Decision: 已落库的简洁模式初始化数据不自动清理。
  - Reason: 这些记录已经是普通业务实体，无法可靠区分是否仍被生产流量使用。

## Risks / Trade-offs

- 旧简洁模式实例升级后无法启动。
  - Mitigation: 错误信息明确指出需要删除 `RUN_MODE=simple` 或改为 `standard`，并在文档中提供迁移检查表。
- 标准模式会启用此前被旁路的计费、配额和分组约束。
  - Mitigation: 迁移步骤要求在切换前检查默认分组、API Key 分组、渠道定价、用户余额和配额配置。
- 删除条件分支可能影响依赖简洁模式搭建的测试夹具。
  - Mitigation: 将测试改为显式构造所需依赖，不再借助简洁模式绕过真实前置条件。

## Migration Plan

1. 盘点当前部署是否设置 `RUN_MODE=simple` 或 YAML `run_mode: simple`。
2. 检查管理员和普通用户、API Key 分组、默认分组、渠道映射、余额、配额及计价配置。
3. 在现版本先切换到 `standard` 并完成网关、计费和管理端验收。
4. 升级到移除简洁模式的版本。
5. 如需回滚，恢复旧二进制和旧配置；数据库无需回滚。

## Open Questions

- None. 安全迁移策略固定为显式拒绝旧配置，不执行静默回退。
