# Change: 增加离线回溯风控与高危用户重点监控

## Why

现有内容审计依赖请求入口的实时抽样和历史命中用户全量审查。未被抽中的请求不保存可供二次审查的证据，因此无法在事后发现实时规则的盲区。需要增加风险加权的短期证据采集、每日离线二次审查和持久化用户风险画像，以便将可疑用户升级为重点监控，避免违规流量损害共享上游号池。

## What Changes

- 在请求入口对用户新增内容进行可配置的风险加权抽样，对单用户设置每日证据数量和字节上限，不重复保存完整对话历史。
- 增加加密证据存储端口和阿里云 OSS 适配器，原始证据存入 `sicts/risk-evidence/*`，PostgreSQL 只保存索引、审查结果和风险事件。
- 增加单实例、幂等、有预算上限的每日离线审查任务，使用独立的二次审查策略处理前一天的证据。
- 增加持久化用户风险画像和风险事件，支持正常、观察、高危、严重四档，并复用现有高危用户 100% 实时审查与分级处置能力。
- 离线单次命中默认只升级重点监控，不直接封禁用户；重复高置信命中或管理员复核后才能进入现有 Key/用户处置链路。
- 在风控中心增加离线巡检运行状态、高危用户、风险事件、证据保留和人工复核界面。
- 使用现有全局阿里云凭证仅执行一次性引导：创建项目专用 RAM 身份和 AccessKey，运行时仅允许访问 `sicts/risk-evidence/*`，不在代码库、数据库或日志中保存全局凭证。
- 第一期不引入向量数据库；如后续需要聚类变体话术，再单独评估脱敏向量和 `pgvector`。

## Impact

- Affected specs: `content-moderation-enforcement`
- Affected code: 内容审计领域模型与仓储、网关请求规范化、OSS 证据存储适配器、夜间审查任务、风险画像和管理 API/界面
- Affected infrastructure: 阿里云 OSS Bucket `sicts` (`oss-us-east-1`)、项目专用 RAM 身份、生产密钥注入和 OSS 生命周期/加密策略
- Database: 需要新增证据索引、审查运行、风险事件和用户风险画像表
- Compatibility: 新能力默认关闭；不改变现有实时审计、分级禁用和 `cyber_policy` 计数语义
