# Change: 稳定账号周额度满额预估

## Why

当前“满额预估”直接使用窗口累计账号成本乘以 `100 / used_percent`。本地成本会随每个请求连续增长，而上游百分比只在额度快照刷新时阶梯变化；在 1%～10% 的低利用率阶段，微小采样误差会被放大 10～100 倍，导致同为 Pro 的账号显示出相差数百美元的伪精度结果。

## What Changes

- 持久化账号额度窗口的离散观测点，记录观测时刻的上游利用率和与该时刻对齐的本地累计消耗
- 优先使用同一窗口内多个观测点的 `成本增量 / 利用率增量` 估算满额成本，避免连续分子除以阶梯分母
- 对样本不足的窗口执行明确降级：低于 5% 不显示金额，只有累计样本时标记为低置信度
- 为满额预估返回估算方法、样本跨度、置信度和区间，前端不再把粗略外推展示为确定额度
- 观测写入只在上游 used% 发生有效变化时执行，并通过窗口索引限制聚合与查询开销
- 不改变上游额度探测、账号调度、计费入账和利润核算口径

## Impact

- Affected specs: `account-quota-estimation`
- Affected code: OpenAI 额度快照持久化、账号窗口统计服务、账号用量 API 类型、`UsageProgressBar.vue`、相关后端与前端测试
- Database impact: 新增额度利用率观测表及按账号窗口查询索引
- Compatibility: 保留现有 `full_*` 字段；新增估算元数据，样本不足时允许省略 `full_*`
