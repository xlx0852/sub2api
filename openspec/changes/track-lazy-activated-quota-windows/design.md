## Context

账号的付费订阅周期与厂商滚动额度窗口是两层独立事实。厂商可以在订阅期内提前清零周用量，也可以在清零后等到第一次真实使用才启动新的七天倒计时。

## Goals / Non-Goals

- Goals: 保留厂商真实切窗事件、待激活空档和付费周期的绝对裁剪边界。
- Goals: 使配额窗口收入与订阅周期总利润可以解释和对账。
- Non-Goals: 不改变收入、API Key 计量成本或订阅采购成本的计算口径。

## Decisions

- 厂商原始窗口保存在 `account_quota_windows`；Profit 展示时再与已记账订阅周期求交集，不破坏原始窗口事实。
- 厂商清零时允许一个 `account_id + kind` 暂时没有 open 行；不创建假的新窗口。
- 待激活空档由已关闭窗口的 `end_at` 和下一条真实窗口的 `start_at` 派生；当尚未激活时，空档终点为当前时间或订阅截止时间。
- 正常倒计时中 `observed_at + reset_after_seconds` 应基本稳定；该时间向未来跳变超过容差时，即使新旧理论区间重叠，也视为真实重置。
- 过期 open 窗口在其已知 `end_at` 关闭并进入待激活；第一次后续真实观测以 `reset_at - period` 推导激活时间并开窗。
- 订阅空档不归属任何厂商窗口，但仍属于付费订阅的空闲时间，不改变周期固定成本。

## Risks / Trade-offs

- 只有 `used_percent` 而没有可信 `reset_at/period` 时无法唯一确定重置；系统保持待确认，不仅凭用量下降造窗。
- 主动模型推理探针会改变待激活状态；保底巡检只允许调用不消耗额度的使用量查询。

## Migration Plan

- 在现有窗口表上增加最后观测时间，历史行保持不变。
- 已过期但仍 open 的行在新逻辑首次扫描时按已知 `end_at` 关闭。
- 上线后通过新账本行开始累积准确空档，不伪造上线前未观测的历史激活时间。
