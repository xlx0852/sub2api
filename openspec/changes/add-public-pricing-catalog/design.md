# Design: 匿名公开价格清单

## 数据边界

公开快照从已启用渠道关联的已启用、非专属分组生成。每个模型仅保留：

- 模型标识、展示名、平台、类型标签；
- 公开候选分组应用默认倍率和高峰倍率规则后的有效价格；
- 当前公开候选中的最低价格；
- 快照版本与生成时间。

快照不包含渠道、分组、账号、用户、成本、上游地址和凭据相关字段。登录态 `/channels/available` 及 `/model-catalog` 保持不变。

## 缓存与抗放大

1. L1 进程内缓存保存已编码 JSON、ETag 和生成时间，匿名命中不访问 Redis 或数据库。
2. L2 Redis 保存同一份快照，建议有效期 24 小时；L1 建议新鲜期 1 小时。
3. L1 过期时优先返回旧快照，并由单个后台任务重建；同一实例只允许一个重建任务。
4. 多实例使用 Redis 短锁约束重建；未获得锁的实例返回 L2 或本地旧快照。
5. 重建失败不清除最后成功快照；仅在首次启动且没有任何快照时同步生成一次，其他并发请求快速返回 `503`，不得并发回源。
6. 响应设置稳定内容哈希 `ETag`；匹配 `If-None-Match` 时返回 `304`。
7. 响应建议设置 `Cache-Control: public, max-age=300, s-maxage=3600, stale-while-revalidate=86400, stale-if-error=86400`。
8. 公开接口使用独立 IP 限流，默认建议每 IP 每分钟 60 次、突发 20；生产 Nginx/CDN 同步配置源站限速和连接限制。

## 失效策略

渠道、分组、分组倍率、模型定价、模型目录或公开功能开关发生管理写入后，只标记快照过期，不在写请求内同步重建。后台重建成功后原子替换 L1/L2。匿名请求不接受 `refresh`、`no-cache` 等绕过参数。

## 前端

在公开首页嵌入价格区段，使用首页既有品牌布局并提供紧凑模型卡片与筛选组件。匿名区段不展示渠道和分组数量、不展示可用渠道标签；登录态页面继续展示完整用户可见信息。首页导航通过锚点定位价格区段。

## 验证

- 单测公开 DTO 白名单与专属分组排除。
- 单测缓存命中不查询数据库、并发缺失只重建一次、失败返回旧快照。
- Handler 测试 `ETag`、`304`、缓存头、限流和首次无快照快速失败。
- 前端测试匿名路由、筛选、空态及不渲染渠道/分组内部信息。
