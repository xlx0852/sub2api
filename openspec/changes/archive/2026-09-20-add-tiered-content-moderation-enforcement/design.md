## Context

内容审计日志已保存用户和 API Key 标识，现有副作用会统计用户窗口内的违规次数，并在达到阈值时禁用用户。API Key 已有 `active` / `disabled` 状态和认证缓存失效机制。

## Goals / Non-Goals

- Goals: 建立“单次命中禁用 Key，多次命中禁用用户”的两级处置，且每一次状态变更可审计。
- Non-Goals: 不自动删除 Key，不自动恢复 Key，不改变违规分类或分数阈值计算。

## Decisions

- Decision: 轻微触发指任意一次会进入违规计数的新命中，处置对象是当前请求携带的 `api_key_id`。
- Decision: 多次触发继续按用户维度使用现有窗口和阈值，即使用户更换 Key 也会累计。
- Decision: 状态变更顺序为“准备审计元数据 -> 写入日志 -> 禁用 Key/用户 -> 失效缓存 -> 发送通知”，避免无日志的自动禁用。
- Decision: Key 不存在、不属于该用户、已禁用或当前请求没有 Key 标识时，不扩大处置到其他 Key，只记录结果。

## Risks / Trade-offs

- 单次误判会使当前 Key 不可用。通过默认关闭新策略、保留管理员手动恢复能力和完整日志降低风险。
- 日志落库成功但禁用失败时，必须记录明确错误且不得把通知描述为“已禁用”。

## Migration Plan

新增幂等数据库迁移，为内容审计日志增加 Key 禁用结果和自动处置错误字段。新配置字段不存在时按 `false` 处理，先发布后由管理员在风控界面显式启用。回滚时可保留新列，旧版本不读取它们。
