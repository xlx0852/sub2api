## Context

当前 `ModelPricing` 与 `ChannelModelPricing` 把所有价格注释为 USD，`usage_logs.total_cost` 保存基础成本数值，`actual_cost` 保存乘分组倍率后的用户扣费，`account_rate_multiplier` 保存账号成本倍率快照。利润查询以 `actual_cost` 为收入，以账号侧基础成本乘 `account_rate_multiplier` 为 API Key 账号成本。

这些数值已经支持销售与采购分离，本改动不引入外汇引擎，而是把现有倍率的业务语义收敛为可审计的三层模型。

## Goals / Non-Goals

- Goals:
  - 模型基础价格可明确标记 `USD` 或 `CNY`。
  - 用户余额和实际扣费统一为无币种平台额度。
  - 平台不负责上游外汇，管理员通过综合成本倍率管理实际采购成本。
  - 新用量保存定价币种与倍率快照，后续改价不改变历史利润。
  - DeepSeek 改用中文官方人民币定价，Codex/OpenAI 保留美元基础价数值与现有销售倍率。
- Non-Goals:
  - 不读取实时或历史汇率。
  - 不自动根据账号充值记录推导综合成本倍率。
  - 不转换现有用户余额、充值、配额和历史用量数值。
  - 不把不同基础币种的 `total_cost` 直接汇总为财务收入或成本；跨模型汇总只使用额度口径。

## Decisions

### Decision 1: 定价币种是基础价格元数据，不是自动换算指令

- `PricingCurrency` 仅允许 `USD` 和 `CNY`，内部规范化为大写。
- LiteLLM 远程价格默认为 `USD`；模型目录和渠道覆盖可显式指定币种。
- 渠道覆盖价格生效时，该渠道币种与其价格一起生效；不允许同一个定价条目内混用两种币种。
- 计费引擎不接收 `fx_rate`，也不根据请求时间查询汇率。

### Decision 2: 平台余额是无币种额度

- 用户扣费公式保持为 `base numeric price × sales multiplier`。
- `actual_cost`、用户余额、API Key 配额和分销收益属于平台额度口径，展示时不带 `$` 或 `¥`。
- 充值货币和支付金额仍属于支付账本，不因额度去币种而丢失真实支付币种。

### Decision 3: 账号倍率是管理员维护的综合成本倍率

- 账号侧按量成本公式保持为 `account-side base numeric cost × account comprehensive cost multiplier`。
- 综合成本倍率可同时包含汇率、上游折扣、充值手续费和保守缓冲；平台不拆分或验证其组成。
- 保留数据库和 API 字段名 `rate_multiplier` / `account_rate_multiplier` 以降低迁移风险，但管理端标签、帮助文本和利润解释统一使用“综合成本倍率”。
- 首期保留账号级默认倍率；如单一账号下的不同模型成本比例不同，管理员使用能覆盖实际成本的保守倍率。按模型覆盖不在本次首发范围内，避免在尚无真实需求时增加第二套配置优先级。

### Decision 4: 新用量快照定价币种，历史数值不回算

- `usage_logs` 新增可空 `pricing_currency`；新写入必须保存解析后的币种。
- 历史空值在 DTO 展示上兼容为 `USD`，但不通过批量 SQL 改写历史日志。
- 现有 `actual_cost` 已是用户扣费快照，`account_rate_multiplier` 已是账号成本倍率快照；不新建重复的账号成本列。
- 持久化结算 payload 增加币种字段并保持向后兼容，重试时不根据当前配置重新解析币种。

### Decision 5: 基础币种符号与无单位结算数值分离

- 模型基础单价、输入/输出基础费用和“原始”基础价始终显示快照币种符号；`CNY` 显示 `¥`，`USD` 显示 `$`。
- 旧模型、LiteLLM 远程价格和旧用量缺少币种时必须补齐为 `USD` 并显示 `$`，价格界面不得输出空单位。
- “用户扣费”、用量列表绿色费用、账号成本与利润汇总只显示数字，不添加货币符号，也不追加“额度”或“成本额度”单位文字。
- 公开价格清单的模型基础价格同样始终显示 `$` 或 `¥`；对用户最终有效价格只显示数字，不将它宣称为美元或人民币。

## Risks / Trade-offs

- DeepSeek 从美元基础数值切换为人民币基础数值后，相同分组倍率的用户扣费会明显增加。
  - Mitigation: 将 DeepSeek 价格、相关分组销售倍率与 API Key 账号综合成本倍率作为同一切换批次，上线前用固定 token 用例核对。
- 一个账号级综合成本倍率无法精确表达所有模型和 token 类型不同的价差比例。
  - Mitigation: 首期使用保守倍率，并在配置界面实时预览样例成本和毛利；真实出现账号内多模型差异后再独立增加模型覆盖。
- 历史日志缺少币种快照。
  - Mitigation: 历史展示兼容为 USD 并保留原数值；不把兼容标签作为重算依据。
- 运营人员可能继续把综合成本倍率当作单纯折扣。
  - Mitigation: 重命名管理端标签，补充公式、样例预览和修改生效时间提示。

## Migration Plan

1. 发布币种元数据与兼容读取，所有未配置价格继续按 `USD` 处理。
2. 发布新用量的 `pricing_currency` 双写、基础价格币种符号和无单位结算数值展示，验证 Codex/OpenAI 扣费数值不变。
3. 在切流前生成 DeepSeek 配置对照：中文官方基础价、分组销售倍率、每个 API Key 账号的综合成本倍率及预期毛利。
4. 在同一发布/配置窗口切换 DeepSeek CNY 定价和相关倍率，不批量改写历史用量。
5. 对固定 DeepSeek Flash / Pro 峰时、谷时、缓存命中/未命中用例核对用户扣费、账号成本和利润；再验证 Codex 样本无变化。

## Rollback

- 回滚应用到旧版本并同时恢复 DeepSeek 分组/账号倍率配置快照。
- 新增币种字段保留不删除；旧版本忽略它们。
- 已写入的用量日志不回算，回滚只影响后续请求。

## Open Questions

- 无。平台明确不自动管理汇率，DeepSeek 首期使用账号级保守综合成本倍率。
