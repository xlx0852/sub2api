# Change: 增加内容审计分级拦截策略

## Why

现有内容审计在单次命中时只会拦截当前请求，达到累计阈值后则直接禁用整个用户。这使轻微或首次命中后的处置过于宽松，而下一级处置又过重。需要在两者之间增加“先禁用当前 API Key”的分级处置。

## What Changes

- 在命中通知配置中增加轻微触发策略：启用后，单次有效违规命中先禁用发起请求的 API Key。
- 保留现有多次触发策略：用户在累计窗口内达到封禁阈值后，再升级为禁用用户账号。
- 禁用 Key 后立即失效对应认证缓存，使后续请求不再使用该 Key。
- 审计日志区分“已禁用 Key”与“已禁用用户”，通知文案按实际处置结果发送。
- 保持 `cyber_policy` 是否计入累计封禁的现有配置语义；被排除时不执行任何自动处置。

## Impact

- Affected specs: `content-moderation-enforcement`
- Affected code: 内容审计配置、命中副作用、API Key 仓储与认证缓存、风控管理界面、审计日志与邮件通知
- Compatibility: 新开关默认关闭，旧配置与现有封号行为保持不变
